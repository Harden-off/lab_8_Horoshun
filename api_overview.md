# 🔌 Технічна документація REST API (`API_OVERVIEW`)

Цей документ містить опис базових програмних інтерфейсів (REST API) системи **DormHub** для обміну даними між вебклієнтом, мобільним застосунком мешканця та сервером управління гуртожитком.

## 🌐 Базові параметри API

- **Базовий URL:** `http://localhost:3000/api/v1`
- **Формат обміну даними:** `application/json` (кодування UTF-8)
- **Авторизація:** Bearer-токен у заголовку `Authorization: Bearer <token>`

## 📡 Основні Endpoint'и

### 1. Отримання списку кімнат та вільних місць
Повертає перелік кімнат гуртожитку з можливістю фільтрації за поверхом і наявністю вільних ліжко-місць.

- **Метод та шлях:** `GET /api/v1/rooms`
- **Query-параметри (необов'язкові):**
  - `floor` (число) — номер поверху (наприклад, `3`)
  - `available_only` (логічне значення) — показати лише кімнати з вільними місцями (`true` / `false`)

**Приклад запиту:**
```http
GET /api/v1/rooms?floor=3&available_only=true HTTP/1.1
Host: localhost:3000
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR...
```

**Приклад успішної відповіді (`200 OK`):**
```json
{
  "dormitory_id": 4,
  "floor": 3,
  "total_found": 2,
  "rooms": [
    {
      "room_id": 304,
      "room_number": "304-А",
      "capacity": 3,
      "occupied_beds": 2,
      "free_beds": 1,
      "gender_block": "female",
      "status": "available"

    {
      "room_id": 310,

      "capacity": 2,

      "gender_block": "male",
      "status": "available"

}
```

### 2. Подача заявки на поселення студента
Реєструє нову заяву студента на поселення у вибрану кімнату гуртожитку.

- **Метод та шлях:** `POST /api/v1/check-in-requests`

**Приклад запиту (тіло JSON):**
```json
{
  "student_id": "ST-2026-0891",
  "full_name": "Коваленко Ірина Олександрівна",
  "faculty": "Факультет інформаційних технологій",
  "course": 2,
  "preferred_room_number": "304-А",
  "has_medical_certificate": true,
  "comment": "Прошу поселити в один блок зі студенткою Мельник О.В."
}
```

**Приклад успішної відповіді (`201 Created`):**
```json
{
  "request_id": "REQ-5512",
  "student_id": "ST-2026-0891",
  "assigned_room": "304-А",
  "status": "pending_approval",
  "created_at": "2026-08-25T10:15:30Z",
  "message": "Заявку на поселення успішно створено та передано коменданту."
}
```

### 3. Створення заявки на технічний ремонт у кімнаті
Дозволяє мешканцю викликати майстра (сантехніка, електрика, столяра) у свою кімнату.

- **Метод та шлях:** `POST /api/v1/maintenance-tickets`

**Приклад запиту (тіло JSON):**
```json
{
  "room_number": "304-А",
  "author_student_id": "ST-2026-0891",
  "category": "plumbing",
  "priority": "high",
  "description": "Підтікає сифон під умивальником у ванній кімнаті блоку.",
  "preferred_time_slot": "14:00-17:00"
}
```

**Приклад успішної відповіді (`201 Created`):**
```json
{
  "ticket_id": "MT-904",
  "room_number": "304-А",
  "category": "plumbing",
  "status": "new",
  "assigned_technician": "Петренко В. І. (черговий сантехнік)",
  "created_at": "2026-10-12T09:40:00Z"
}
```

## ⚠️ Коди відповідей та помилок HTTP

| Код статусу | Назва | Опис ситуації в системі DormHub |
| :--- | :--- | :--- |
| `200 OK` | Успішно | Запит виконано успішно (наприклад, отримано список кімнат або квитанцій) |
| `201 Created` | Створено | Новий запис (заявка на поселення чи ремонт) успішно створено в базі даних |
| `400 Bad Request` | Некоректний запит | Помилка валідації: пропущено обов'язкове поле (наприклад, не вказано `room_number` або `student_id`) |
| `401 Unauthorized` | Не авторизовано | Відсутній або прострочений токен авторизації мешканця/адміністратора |
| `404 Not Found` | Не знайдено | Кімната або заявка з вказаним ідентифікатором не існує в базі гуртожитку |
| `409 Conflict` | Конфлікт даних | У вибраній кімнаті вже немає вільних ліжко-місць або студент вже має активне поселення |
| `500 Internal Server Error` | Помилка сервера | Внутрішній збій на боці сервера або тимчасова недоступність бази даних |
